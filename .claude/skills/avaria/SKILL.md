# /avaria — прод не работает

Здесь нет плана, ветки от `dev` и веера критиков. Есть порядок, который нельзя нарушать:
сначала бэкап, потом всё остальное. Скажи первой фразой: «Это авария, действую по аварийному
порядку».

## 1. Бэкап — до любых действий

`scripts/rc.sh exec -T backup scripts/backup.sh` — и дождись строки с манифестом. Без свежего
бэкапа дальше не идти, даже если «просто перезапустить».

## 2. Диагноз — по логам, не по догадкам

- `curl -s https://<домен из RUNBOOK>/healthz` — `media:false` означает, что папка фото не
  пишется (уже было в v2.1.1).
- `scripts/rc.sh ps` — все ли контейнеры `healthy`.
- `scripts/rc.sh logs --since 30m bot web worker` — ищи `Traceback`, `ERROR`, `409 Conflict`
  (два бота на одном токене), `Не дозвонился` (прокси на хосте лежит → это к Диме).
- Сверь с `docs/RUNBOOK.md` «Common problems».

Одно предложение Миле сразу: что видишь и что будешь делать. Не жди, пока разберёшься до конца.

## 3. Решение: откат или минимальный фикс

- **Откат** — если сломалось после недавней выкатки или причина не ясна за 15 минут:
  `git switch --detach <предыдущий тег vX.Y.Z> && scripts/deploy.sh && git switch master`.
  Миграции при откате не трогать (они additive).
- **Минимальный фикс** — если причина очевидна и правка в пару строк: ветка `hotfix/<slug>`
  от `master`, правка, `make check`, `git switch master && git merge --no-ff hotfix/<slug>`,
  `scripts/deploy.sh`. Никаких «заодно».
- Хост-уровень (прокси `:10809`, туннель, диск) — не твоя зона: «Это на стороне сервера Димы,
  напиши ему», и что именно передать.

## 4. Проверка

`healthz` → ok; `scripts/rc.sh logs --since 2m bot web worker` без ошибок; напиши тестовое
сообщение боту сам (или попроси Милу): ответил ли.

## 5. Миле — сразу, коротко

Что случилось, что сделал (откат на такую-то версию / фикс), что сейчас работает, что осталось
проверить ей. По-русски, без технических слов.

## 6. После — учёт

- Карточка в `brain/tasks/NN-slug/status.md` с `route: avaria`, `status: on_prod`, журналом
  событий по времени; запись в `brain/bugs/ГГГГ-ММ-ДД-<slug>.md` (симптом, причина, чем
  починено, как не повторить).
- `hotfix/` влить и в `dev`: `git switch dev && git merge --no-ff hotfix/<slug> && git push origin dev`.
- `git push origin master --tags` (после нового тега `vX.Y.Z+1`, строка в `docs/CHANGELOG.md`).
- Разбор и полноценный отчёт (`/otchet`) — отдельной задачей, когда всё работает.
