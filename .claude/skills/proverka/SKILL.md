# /proverka — первая ступень: не сломали ли то, что было

Отвечает на вопрос «не стало ли хуже и делает ли правка то, что в плане». Полная проверка
поведения — во второй ступени (`/relize`).

## 0. Условия

Ветка `feature/NN-slug` (или ветка микро-правки), всё закоммичено, `make check` зелёный у тебя
самого. База диффа: `git merge-base dev HEAD`. Открой `brain/tasks/NN-slug/status.md` — там
приёмка.

## 1. Верификатор

Агент `verifier` (subagent_type `verifier`): `make check` + команды, которые задача добавила.
Красное — чинишь код и запускаешь снова; тесты не ослабляй.

## 2. Критики — параллельно, одним сообщением

- `critic-code` — дифф `git diff <base>..HEAD`, задание из карточки, три линзы (корректность,
  безопасность, чистота).
- `critic-ui` — стенд в режиме «работа» (`/stend up`), сценарии из раздела «Приёмка» плана,
  по 2–3 злых сценария на каждый, плюс короткий смоук: /start → задание → отчёт текстом →
  паспорт → админка «Неделя». Скриншоты — в `.dev/shots/`. После сценариев — grep логов стенда.

**Лёгкий режим** (`--light`, микро-правка): только `verifier` и `critic-code`; экран, где
изменился текст, посмотри сам через `scripts/shots.sh` и приложи скриншот.

## 3. Правки и повтор

Каждую critical/important находку чини сам (агенты код не пишут). Повторный запуск — только
того критика, у которого были блокирующие находки, с перечнем внесённых правок. Не больше трёх
раундов; что осталось — честно в карточку и Миле.

Находку можно отклонить только с причиной (противоречит плану или DOMAIN, ревьюер не понял
контекст) — причину запиши в журнал карточки.

## 4. Итог в карточку

В `status.md`: галочки приёмки (только по тому, что реально прогнано), строка в журнал:
дата, «проверка: make check N из N, критик кода — k находок / закрыто, критик поверхности —
сценарии …», ссылки на скриншоты. `python3 scripts/brain_index.py`.

## 5. Миле

По-русски, коротко: что проверено и как (числа, сценарии), что нашли и починили, что осталось.
Предложи: «сливаю в dev?». Если она хочет посмотреть сама — `/stend` и ссылки.

После её «ок»: `git switch dev && git pull --ff-only && git merge --no-ff feature/NN-slug &&
git push origin dev`; `status: in_dev`; журнал; индекс. Ветку задачи не удаляй до релиза.
