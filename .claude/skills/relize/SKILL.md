# /relize — вторая ступень и выкатка на прод

Отвечает на вопрос «точно ли работает как задумано» и делает выкатку. Только по прямой просьбе
Милы. Ничего здесь не идёт на прод без её слова «выкатываем» на шаге 6.

## 0. Условия

- Задачи релиза в `brain/tasks/` со `status: in_dev`; их ветки влиты в `dev`.
- `git switch dev && git pull --ff-only`; `make check` зелёный на `dev`; последний CI на
  `dev` зелёный (Мила видит на GitHub во вкладке Actions; без доступа — верификатор ниже).
- Стенд: `/stend up` (режим «работа»). База диффа релиза: `git merge-base master dev`.

## 1. Полный веер — параллельно, одним сообщением

Агенты — через Agent tool с `subagent_type` ровно по имени файла в `.claude/agents/`:

- `verifier` — `make check` со знаменателями на `dev`.
- `critic-code` — дифф `master..dev`, все задачи релиза в задании.
- `critic-ui` — регресс-список целиком (/start → задание → отчёт текстом → отчёт с фото →
  правка отчёта → паспорт → словарь → журнал → PDF → админка: неделя, люди, письма →
  напоминание «сейчас») плюс приёмка каждой задачи релиза; после сценариев — grep логов.
- `critic-data` — обязательно, если дифф трогает `romantika/db/`, `romantika/worker/`,
  `romantika/ops/`, `romantika/pdf/`, `romantika/services/{media,reports,stamps,freezes}.py`,
  `scripts/backup.sh`, `scripts/restore-verify.sh` или `docker/`; иначе по желанию.
- `critic-limits` — границы и параллелизм по тем местам, которых коснулись задачи; перед
  первым релизом после долгого перерыва — весь список.

Каждому агенту — карточки задач и правило: находка без доказательства не находка; в отчёте
обязательны строки логов.

## 2. Правки и повтор

Critical/important — чинишь сам в ветке `feature/…` (или короткой ветке `fix/…` от `dev`),
`make check`, вливаешь в `dev`, перезапускаешь только упавших критиков. До трёх раундов. Что
осталось — честно в отчёт и Миле; блокирующие остатки = релиза нет.

## 3. Живой прогон в настоящем Telegram

`/stend up --live`. Скажи Миле, что открыть и что нажать — список из приёмки задач своими
словами плюс пять базовых действий (/start, задание, отчёт с фото, паспорт, админка). Пройди
то же сам с тестовым ботом. Живой прогон агентами не заменяется. Отдельного подтверждения
здесь нет: её замечания — это правка и шаг 1 для затронутого критика, а её слово — на шаге 6.

## 4. Отчёт

`/otchet отчёт NN` для каждой задачи релиза (пары «было — стало», что проверено с числами и
строками логов, что осталось). Редактор `editor-report` — обязателен. Ссылки Миле.

## 5. Журнал изменений и версия

`docs/CHANGELOG.md`: новый раздел `## vX.Y.Z — ГГГГ-ММ-ДД` — что изменилось для участниц, что для
Милы, что под капотом (по-английски, как соседние). `docs/GUIDE-RU.md` — если изменилась её
рутина. Коммит в `dev`.

## 6. Окно и слово Милы

Сними активность: `scripts/prod-snapshot.sh --brief` (только чтение; запросы названы в
RUNBOOK) — сколько человек писали боту за сутки и за час. Снимок «неполный» — так и скажи,
окно по нему не выбирай. Ритм клуба: понедельник утром пост, четверг
19:00 и воскресенье 12:00 напоминания, воскресенье вечером «Привал» — в эти часы не катим.
Скажи Миле: «За последние сутки в боте N человек, за последний час M. Сейчас <день, время>.
Выкатываем сейчас или подождём <окно>?» Ждёшь «выкатываем»; после него карточки задач —
`status: ready_for_prod`.

## 7. Выкатка

1. `git switch master && git pull --ff-only && git merge --no-ff dev && git tag vX.Y.Z`.
2. `DRY=1 scripts/deploy.sh` — в списке нет ничего лишнего (`.env`, данные, `.dev`).
3. `scripts/deploy.sh` (Claude Code спросит подтверждение — это нормально).
4. `curl -s https://<домен из RUNBOOK>/healthz` → `"status":"ok"`; `scripts/rc.sh logs --since 2m
   bot web worker` две минуты — нет ошибок; открой бота и приложение один раз.
5. `git push origin master --tags` (подтверждение), `git push origin dev`.
6. Карточки: `status: on_prod`, журнал, `python3 scripts/brain_index.py`. Ветки задач можно
   удалить: `git branch -d feature/NN-slug`.

Что-то красное после выкатки — не чини на ходу: `/avaria` (откат на предыдущий тег).

## 8. Миле

По-русски: что выехало, что проверить самой в настоящем боте, ссылки на отчёты. Через день —
`/prod` и закрыть карточки (`status: closed`), если жалоб нет.
