# restore-verify не проверяет таблицу `letters`

Найден 2026-09-18 критиком данных при `/relize` v2.3.0. Не из этого релиза:
`romantika/ops/backup.py` в диффе не тронут; дефект есть и на `master`.

**Симптом.** `TABLES` в `romantika/ops/backup.py:20` перечисляет 20 таблиц, `letters` среди них
нет — ни в манифесте бэкапа, ни в `last-verify.json`. На стенде (отдельный BACKUP_DIR,
scratch-базы удалены): дамп с копии базы, где пропало 5 писем из 21, →
`uv run python -m romantika.ops.restore_verify` → `ok = True, errors = []`;
`select count(*) from letters` в восстановленной базе → 16.

**Причина.** Сам дамп `pg_dump -Fc` берёт всю базу — письма в бэкапе есть. Но проверка
восстановления сравнивает только таблицы из `TABLES`, и потеря писем не обнаруживается.

**Что предлагаю.** Добавить `letters` в `TABLES` (и `reminder_log`, если её там тоже нет —
проверить). Это `romantika/ops/backup.py` — правило 11: «Это сложное техническое решение —
лучше уточнить у Димы». Риск маленький (только список таблиц для проверки), но конвейер
бэкапов — его зона. До следующего релиза.
