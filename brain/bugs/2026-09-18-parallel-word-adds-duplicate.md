# Два одновременных «своих слова» создают дубль

Найден 2026-09-18 критиком границ при `/relize` v2.3.0. Не из этого релиза: `words.add` и
таблица `words` не менялись.

**Симптом.** Два одновременных `POST /api/words` с одним текстом от одной участницы → две
записи (`select word, count(*) from words where user_id=1029 group by word` → `тест200773 | 5`
при 20 параллельных; при 2 параллельных — дубль в 5 попытках из 5). Заморозка за первое слово
при этом одна (проверено критиком данных отдельно). Слова не удаляются (правило 1), дубль
остаётся в общем словарике и в PDF навсегда.

**Причина.** `romantika/services/words.py:91` `_has_word` — read-then-write без блокировки;
в `words` нет уникального индекса `(user_id, lower(word))`. Для отчётов та же гонка закрыта
`pg_advisory_xact_lock` (`romantika/web/routes/api.py`), для слов — нет.

**Достижимость.** Низкая: кнопка в приложении блокируется на время запроса, диалог в боте
гасится состоянием; остаются два устройства или две вкладки. За сезон на проде ни одного
дубля такого рода не видно.

**Что предлагаю.** `pg_advisory_xact_lock` на `user:word` в `words.add` (без миграции) — и
отдельно, как сложное решение по правилу 11, частичный уникальный индекс миграцией после
чистки существующих дублей руками Милы. Ждёт слова Милы.
