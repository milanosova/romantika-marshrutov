# brain/ — память проекта

Здесь живёт всё, что Claude должен помнить между сессиями: задачи, баги, идеи, снимки
состояния прода и журнал самого харнеса. Папка лежит в репозитории, поэтому история любого
решения — в git. Файлы читает и пишет Claude; Мила открывает планы и отчёты.

Папка **не** `docs/`: `docs/` может раздаваться как сайт (GitHub Pages), а здесь лежат
скриншоты и подробности, которым в интернете не место.

## Состояния задачи

`idea → planned → in_progress → on_stand → in_dev → ready_for_prod → on_prod → closed`

Слово Милы нужно трижды за фичу: `planned → in_progress` («ок» на план), `on_stand → in_dev`
(«сливаем» после первой ступени проверок) и `in_dev → ready_for_prod` («выкатываем»). Для
микро-правки — один раз: её «ок» покрывает и `dev`, и прод. Остальные переходы делает Claude и
пишет строку в журнал карточки. Кто какой переход делает: `/zadacha` — `planned`, `in_progress`;
`/proverka` — `on_stand`, `in_dev`; `/relize` — `ready_for_prod`, `on_prod`; `/prod` через день —
`closed`. Задача без движения больше месяца помечается `status: parked` с
причиной.

## Правила

- Одна задача — одна папка. Новая сущность — новый файл, не разрастание существующего.
- Даты абсолютные (`2026-09-16`), не «вчера».
- Журнал карточки — только дописывать в конец.
- Персональных данных участниц здесь нет: скриншоты только со стенда с демо-данными.
- Баг, найденный критиком во время `/proverka` или `/relize` и починенный сразу, — строка в
  журнале карточки; баг, отложенный или найденный на проде, — файл в `bugs/`.
